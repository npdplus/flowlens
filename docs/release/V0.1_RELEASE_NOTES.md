# FlowLens v0.1.0 Release Notes

FlowLens v0.1.0 is the first open-source release baseline of **NPD PLUS Labs / Experimental Open-source** for turning JSON/YAML workflow definitions into validated, analyzed, interactive workflow diagrams.

> **Understand. Validate. Visualize.**

## Highlights

- Native FlowLens Workflow Definition schema `0.1` in JSON or YAML.
- Local `.json`, `.yaml`, and `.yml` file opening.
- CodeMirror 6 editing with syntax highlighting and line numbers.
- Structural validation and stable `FL####` diagnostics.
- Semantic validation for graph references and topology.
- Workflow analysis kept separate from validation outcomes.
- Automatic ELK layout and read-only React Flow visualization.
- Pan, zoom, fit view, selection, and Inspector details.
- Keyboard-focusable diagram entities with semantic keyboard selection.
- Light and dark themes.
- Local SVG and PNG diagram export.
- Five synthetic built-in examples: Simple Sequential, Purchase Approval, CI/CD Deployment, AI Agent Workflow, and Incident Response.
- No account, backend, database, or cloud workflow-storage requirement for the V0.1 core workflow.

## Local-first privacy and security

Workflow input is treated as untrusted data.

V0.1 core behavior does not require uploading workflow definitions. Conditions and metadata remain data rather than executable logic. The application does not use `eval` or a Function constructor for workflow content, does not require raw untrusted HTML rendering, and performs SVG/PNG export locally from the rendered diagram.

Release verification found no tracked secret patterns in the candidate tree and no workflow-content network requests in the verified browser production journeys.

See `SECURITY.md` for the supported security model and vulnerability-reporting guidance.

## Browser verification

The release browser matrix passed on the Linux release runner in:

- Google Chrome `151.0.7922.137`
- Microsoft Edge `151.0.4129.86`
- Playwright Firefox `150.0.2`
- Playwright WebKit `26.4`

The matrix completed with 33 passed test-project combinations and 3 intentional performance-test skips; the browser performance probe runs only in branded Google Chrome. WebKit is used as a Safari-engine compatibility proxy and is not evidence of native Safari/macOS verification.

The WebKit result is a **Safari-engine compatibility proxy on Linux**, not a claim that Safari on macOS was directly tested. Safari/macOS remains unverified for this release unless separate native testing is performed.

Browser verification covers JSON/YAML production paths, all five official examples, invalid-input safety, local export behavior, baseline keyboard/focus/accessibility behavior, and absence of workflow-content external requests in the tested journeys. It is not a formal WCAG certification.

## Representative performance observations

Synthetic sequential workflows were measured in release CI. These categories are test workloads, not guaranteed maximum supported sizes.

| Category | Steps | Transitions | Core processing | ELK layout | Total processing + layout |
| --- | ---: | ---: | ---: | ---: | ---: |
| Normal | 100 | 99 | 7.25 ms | 173.68 ms | 181.32 ms |
| Large | 500 | 499 | 12.05 ms | 379.98 ms | 392.74 ms |
| Stress | 1,000 | 999 | 44.56 ms | 443.62 ms | 488.30 ms |

A branded Chrome browser probe measured editor-input-to-render readiness and fit-view interaction on generated sequential workflows:

| Category | Steps | Render ready | Fit view |
| --- | ---: | ---: | ---: |
| Normal | 100 | 1,087 ms | 22 ms |
| Large | 500 | 4,929 ms | 953 ms |
| Stress | 1,000 | 6,140 ms | 37 ms |

For the 100-step case, local export measured approximately 1,403 ms for SVG (20,984,233 bytes) and 3,956 ms for PNG (340,641 bytes). These are GitHub-hosted CI observations, not performance guarantees.

Results depend on graph shape, labels, branching, browser/device resources, viewport/export dimensions, and future dependency versions. They should be treated as observations from the recorded CI environment, not performance guarantees.

## Build-size note

The verified production build intentionally retains Vite's large-chunk warning in V0.1. The main JavaScript bundle was approximately **2.28 MB minified / 710 KB gzip**, and the main CSS bundle was approximately **27.9 KB minified / 5.65 KB gzip** in the release-verification environment.

Bundle splitting is a future optimization opportunity and was not allowed to expand P10 into V0.2 work.

## Known limitations

- Desktop-first browser experience.
- Native FlowLens schema only; no BPMN, GitHub Actions, n8n, Power Automate, or other external adapters in V0.1.
- No visual workflow authoring or workflow execution.
- No authentication, cloud workflow storage, collaboration, or runtime monitoring.
- No AI workflow generation/explanation.
- No stable public CLI/SDK compatibility guarantee.
- Very large or highly connected graphs may have different layout/render/export costs than the synthetic sequential verification workloads.
- PNG export bounds raster dimensions to a maximum of `8192px` per dimension, which can trade resolution for bounded raster size on very large diagrams.
- Safari/macOS was not directly verified by the Linux browser matrix.

## Installation

Prerequisites:

- Node.js `24.18.0`
- pnpm `11.4.0`

```bash
corepack enable
corepack prepare pnpm@11.4.0 --activate
pnpm install --frozen-lockfile
pnpm dev
```

Create a production build with:

```bash
pnpm build
```

Repository verification commands are documented in `README.md` and `CONTRIBUTING.md`.
